AllFish

AllTrails for anglers — a map-first web app to discover every river, lake, and pond, with cited sources for where the water is and what fish are in it, plus community reports on the fishing.

What shipped

A working Google-Maps-like fishing map

Real OpenStreetMap geometry for every water body, a list + map + detail layout modeled on AllTrails, species filtering, name search, a Google-Maps-style “Search this area” control, and a live community-report system — all backed by an API whose reads are cache-ready and whose only write path is rate-limited and sanitized.

A reusable ingestion pipeline then inventoried every named lake, pond, and river within 50 miles of Boston and across all of New York State — 18,000+ water bodies — each classified fresh / salt / mixed from OpenStreetMap tidal/salt tags (basis shown and cited) and rendered with a per-feature OSM permalink. Filters let you narrow by water type, salinity, or “has fish data.” Where no fish are documented, the app says so honestly (a data gap, not a survey) and links a live iNaturalist query for that exact water so the “0” is verifiable.

The build, by task

Plan → architect & secure → QA

Task 0

Strategy, research & data

Delivered

Acting as CPO + CSA: a north-star metric, personas, and a positioning wedge built from real competitive research — a 19-agent workflow mined competitors (Fishbrain, onX, Navionics, Angler's Atlas) and voice-of-customer (App Store reviews, Reddit), then adversarially fact-checked every licensing and data claim (0 refuted).

  • The wound to exploit: incumbents paywall the basics and ship "dead wrong" data. AllFish answers with an honest free tier + cited data.
  • Legally-shippable data foundation confirmed: US NHD is public-domain; ODbL (OSM) & CC-BY-NC (FishBase) segregated.
Task 1

Architecture, security & build

Delivered

An engine-agnostic data layer (all SQL isolated to one repository module) so SQLite → PostGIS is a swap, not a rewrite. A senior security review ran against the code: SQL injection, path traversal, CSRF, and ReDoS all confirmed clean; the one high finding (rate-limit bypass via X-Forwarded-For) was fixed, along with bbox hardening and HSTS.

  • Scale path: 10 users (one process) → 1k (CDN + cached reads) → 100k+ (PostGIS + read replicas + self-hosted PMTiles vector tiles).
Task 2

QA — proven working

Delivered

Driven end-to-end in a real browser: the map renders, water bodies plot at correct coordinates, the detail panel shows live citations, and a review posted through the UI persisted to the database. A reproducible 10-test suite covers health, bbox, detail, species filter, the review write path, input validation, and security headers — all green.

Provenance model

Two claims, two citations

The product requirement — cite the source that shows there's water, and cite the source for each species — is implemented as schema, not decoration.

ClaimHow it's sourcedExample
"There is water here" USGS NHD (US) / NRCan NHN (CA) + the exact OpenStreetMap feature permalink captured when the shape is drawn openstreetmap.org/relation/1823287 Public domain
"This species is here" State/provincial fish & wildlife agency, stocking record, or iNaturalist research-grade query — each with its own confidence Walleye — MN DNR survey Documented · Fathead Minnow — iNaturalist Reported

Run it

# from /app
npm install

npm run seed             # cited data + reviews → SQLite
npm run build:client
npm start                # → http://localhost:8787
